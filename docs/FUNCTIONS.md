# 功能清单

> 更新时间：2026-08-06
>
> 本文档基于当前仓库代码、README、API 文档和 HANDOFF 交接文档整理，主要用于快速了解系统已经具备的能力，以及后续仍未完成或需要外部条件验证的功能。

## 项目定位

AI 鉴股是一个本地可运行的 A 股研究、筛选和监控工具，核心能力包括数据采集、规则评分、多因子排序、DeepSeek AI 研判、行业轮动、回测、交易计划、模拟盘和浏览器仪表盘。

当前系统不应被定位为自动赚钱策略或实盘自动交易系统。已有研究结论显示：原始综合评分的截面选股 alpha 较弱，后续接入的因子倾斜组合有一定改善，但仍需要持续样本外监控和更多数据验证。

## 已实现功能

### 1. 数据采集与本地存储

- 支持 `akshare` 数据源，主要用于东方财富相关行情、资金和公告数据。
- 支持 `baostock` 备用数据源，适合网络受限环境下拉取 A 股日线、估值、财务和指数成分数据。
- 支持股票基础信息、日线行情、财务数据、估值数据、行业指数、公告新闻、资金流和评分结果入库。
- 默认使用 SQLite，本地数据库路径为 `data/db/stock_analyzer.db`。
- 通过 `DATABASE_URL` 支持切换到 PostgreSQL 等 SQLAlchemy 兼容数据库。
- 支持数据缓存、重试、超时、并发更新和失败跳过。
- 支持按全市场、样本数量、指定股票代码、指定指数成分股更新数据。
- 支持历史季度财务回填，用于 point-in-time 因子研究。

相关入口：

- CLI：`ai-stock update-data`
- CLI：`ai-stock update-news`
- CLI：`ai-stock update-capital`
- 脚本：`scripts/backfill_fundamentals.py`
- 脚本：`scripts/populate_financials.py`
- 脚本：`scripts/fetch_backtest_history.py`

### 2. 规则评分引擎

- 已实现 6 个评分引擎：
  - 价值引擎：估值、财务质量、盈利能力等。
  - 趋势引擎：动量、均线、波动等量价趋势。
  - 资金引擎：真实主力资金优先，缺失时使用量价代理指标降级。
  - 行业引擎：行业热度和行业相对表现。
  - 事件引擎：事件类数据不足时自动降权。
  - 消息引擎：基于公告标题做规则化利好、利空识别。
- 支持数据不足时引擎不参与综合评分，避免用默认 50 分伪造信号。
- 支持输出单股各引擎分数、置信度、核心信号、过滤原因和可用引擎数量。

相关入口：

- CLI：`ai-stock score 000001`
- API：`GET /api/v1/stock/{code}/score`
- API：`GET /api/v1/stock/{code}/report`

### 3. 融合排序与风控过滤

- 支持多引擎加权融合生成综合分。
- 支持按市场状态动态调整权重。
- 支持冲突处理：极端分歧隔离；中等分歧按市场状态优先引擎处理，优先引擎不在冲突对内时取较低分。
- 支持基础过滤规则：
  - ST 股票过滤。
  - 新股过滤。
  - 成交额过滤。
  - 停牌过滤。
  - PE 区间过滤。
  - 负债率过滤，金融行业有特殊豁免。
- 支持综合评分落库，供仪表盘、排行和 CSV 导出读取。
- 已接入保守因子倾斜排序：低 PE、ROE、净利润同比、60 日反转组合，支持通过 `FACTOR_TILT_STRENGTH` 开关或调节强度。

相关入口：

- CLI：`ai-stock scan --top-n 20`
- API：`POST /api/v1/scan`
- API：`GET /api/v1/scan/{task_id}`
- API：`GET /api/v1/ranking`

### 4. 市场状态与仓位建议

- 支持识别市场状态：牛市、震荡、熊市、极度恐慌、极度贪婪等。
- 支持将市场状态写入数据库，仪表盘和排行接口优先读取已落库状态，避免每次请求实时访问外部行情。
- 支持按市场状态调整总仓位上限：
  - 牛市：80%
  - 震荡：60%
  - 熊市：40%
  - 极度恐慌：20%
  - 极度贪婪：50%
- 支持按单股评分、市场状态和资金规模生成仓位建议，并执行单股 20%、同行业 40% 上限。

相关入口：

- CLI：`ai-stock regime`
- CLI：`ai-stock position`
- API：`GET /api/v1/regime`
- API：`GET /api/v1/position/suggest`

### 5. 单股估值与交易计划

- 支持历史估值分位分析。
- 支持 PE、PB、PS、股息率等估值指标。
- 支持生成交易计划，包括：
  - 操作方向。
  - 建议买入区间。
  - 止损位。
  - 技术目标价。
  - 价值目标价。
  - 风险收益比。

相关入口：

- CLI：`ai-stock valuation 000001`
- CLI：`ai-stock score 000001`
- API：`GET /api/v1/stock/{code}/valuation`

### 6. DeepSeek AI 研判

- 支持接入 DeepSeek OpenAI 兼容接口。
- 支持单股 AI 分析，输出评级、置信度、结论、看多因素、看空因素、风险和建议动作。
- 支持行业产业链 AI 分析，输出上游、下游、合作配套、风险和产业链受益标的。
- 未配置 API Key、账户不可用或调用失败时，AI 分析会优雅降级，不影响规则评分。

相关入口：

- CLI：`ai-stock analyze 000001`
- CLI：`ai-stock score 000001 --ai`
- CLI：`ai-stock industry-scan --ai`
- API：`GET /api/v1/stock/{code}/ai-analysis`
- API：`GET /api/v1/industry/hot`
- API：`GET /api/v1/industry/chain`

### 7. 行业轮动与产业链分析

- 支持按行业成分股近一年涨幅统计热门行业。
- 支持热门行业内二次选股。
- 支持按行业大小动态控制入选股票数量。
- 支持行业产业链 AI 分析。
- 支持行业热度接口和产业链接口。

相关入口：

- CLI：`ai-stock industry-scan`
- API：`GET /api/v1/industry/hot`
- API：`GET /api/v1/industry/chain`

### 8. 回测与因子研究

- 支持基础组合回测：
  - 月度或周度调仓。
  - Top-N 等权持仓。
  - 综合评分选股。
  - 60 日动量基准。
  - 交易成本、滑点和印花税。
  - 市场状态择时降仓。
  - 指数成分历史 membership，用于降低幸存者偏差。
- 支持回测指标计算。
- 支持因子 IC 研究框架：
  - 量价因子。
  - 基本面因子。
  - 行业和市值中性化。
  - rank-IC、IR、t 值、正比例、多空价差。
  - 滚动样本外验证。
  - IC 加权组合对比。
- 支持因子倾斜回测验证。

相关入口：

- CLI：`ai-stock backtest`
- API：`POST /api/v1/backtest`
- 脚本：`scripts/factor_research.py`
- 脚本：`scripts/factor_tilt_backtest.py`
- 脚本：`scripts/engine_ic_audit.py`
- 脚本：`scripts/classic_factor_ic.py`
- 脚本：`scripts/trade_backtest.py`
- 脚本：`scripts/exit_rule_study.py`
- 文档：`docs/FACTOR_RESEARCH.md`

### 9. 自选股、提醒和 CSV 导出

- 支持服务端持久化自选股。
- 支持自选股分组。
- 支持为自选股设置评分上穿和下破提醒阈值。
- 支持查询当前触发的自选提醒。
- 支持调度器扫描后检查自选提醒，并通过通知服务发送。
- 支持排行 CSV 导出，包含市场状态、评分日、排名、代码、名称、行业、综合分和各引擎分。
- CSV 使用 UTF-8 BOM，便于 Excel 直接打开。

相关入口：

- API：`GET /api/v1/watchlist`
- API：`POST /api/v1/watchlist`
- API：`DELETE /api/v1/watchlist/{code}`
- API：`GET /api/v1/watchlist/alerts`

### 11. 调度、通知、模拟交易和部署

- 支持容器内常驻调度器，每日执行：
  - 数据增量更新。

- 支持本地通知服务，默认输出到日志。

- 支持带风控校验的订单执行引擎。
- 支持基于模拟券商的等权模拟盘服务。
- 支持 Dockerfile 和 docker-compose 部署。
- docker-compose 已包含 API 服务和 scheduler 服务。

### 12. 测试覆盖

- 已有测试覆盖数据层、评分引擎、融合排序、估值、行业、API、回测、风控、LLM、模拟券商、执行引擎、模拟盘、调度器、通知和因子研究。

## 未实现功能

### 1. 真实券商交易

- 尚未接入任何真实券商 API。
- 当前 `broker`、`execution`、`paper_trading` 仅提供本地安全模拟实现。
- 尚未实现真实账户登录、资金查询、持仓同步、委托下单、撤单、成交回报和交易流水同步。
- 尚未实现实盘交易前必须的权限控制、审计日志、人工确认和异常熔断。

### 2. 自动实盘策略闭环

- 尚未实现从评分信号到真实交易账户的自动下单闭环。
- 尚未实现生产级订单路由、订单状态机、失败重试、部分成交处理和交易日历约束。
- 尚未实现实盘组合再平衡、持仓漂移修正和现金管理。
- 当前系统适合研究和监控，不适合作为无人值守自动交易系统。

### 3. 更完整的数据源

- 北向资金、融资融券、股东户数等字段已有数据结构预留，但数据采集仍不完整。
- 自由现金流、分红、现金流质量、ROE 趋势等因子需要进一步补齐和验证。
- 真实主力资金依赖能访问东方财富的网络环境，本机网络受限时无法稳定获取。
- baostock 不提供个股资金流，对应能力会自动降级。
- 行业产业链关系没有免费结构化数据源，目前主要依赖 AI 生成，可能存在偏差。

### 4. 更强的量化 alpha 研究

- 当前因子倾斜组合只是弱而稳的改进，不是强 alpha。
- 尚未完成更长周期、多市况、多市场环境下的滚动样本外验证。
- 尚未实现完整因子库生产化，包括现金流质量、盈利稳定性、分析师预期、北向资金、融资融券、股东行为等。
- 尚未实现行业、市值、风格暴露的生产级风险归因。
- 尚未实现组合优化器、风险预算、行业约束、市值约束和换手率约束。

### 5. 生产级监控和告警

- 当前通知服务默认输出到日志。
- 尚未接入企业微信、钉钉、飞书、邮件、短信或 Push 通道。
- 尚未实现数据更新失败、接口超时、调度失败、评分异常、数据库异常的完整告警体系。
- 尚未实现仪表盘级数据新鲜度 SLA、任务状态追踪和历史运行报表。

### 6. 用户系统和多用户能力

- 尚未实现用户登录、权限管理和多用户隔离。
- 自选股目前是服务端全局表，不区分用户。
- 尚未实现不同用户的自选分组、提醒阈值、偏好配置和操作审计。

### 7. 前端工程化

- 当前仪表盘由后端路由直接返回 HTML。
- 尚未拆分为独立前端项目。
- 尚未实现组件化 UI、状态管理、前端路由、前端测试和构建产物部署。
- 尚未实现移动端专项适配和复杂交互体验优化。

### 8. 数据库迁移后续

- 已建立 Alembic 基线迁移，覆盖空库、未版本化旧库、重复升级和旧自选表补列。
- 已移除运行时 `PRAGMA/ALTER TABLE`，业务层使用 SQLAlchemy repository 查询。
- 后续每次结构变更仍需新增独立 migration，并在目标数据库执行 `alembic upgrade head`。

### 9. API 完整性

- 阶段二/三的调度、通知、模拟券商、执行引擎和模拟盘主要作为 Python 服务模块提供。
- 尚未为所有模拟交易和执行能力暴露完整 REST API。
- 尚未实现 API 鉴权、限流、审计和 OpenAPI 级别的请求/响应示例完善。

### 10. 回测和研究结果产品化

- 因子研究脚本已经具备研究能力，但尚未完全产品化为可交互页面。
- 尚未在仪表盘中提供完整 IC 曲线、因子分组收益、多空组合、滚动样本外结果和回测归因。
- 尚未实现研究结果版本管理、实验追踪和参数对比页面。

## 后续优先级建议

### P0：部署可用性

- 在能访问东方财富的服务器上部署 docker-compose。
- 打通每日调度、真实主力资金刷新、消息面刷新、扫描落库和自选提醒。
- 接入至少一个真实通知渠道。

### P1：产品实用性

- 为仪表盘增加数据新鲜度、任务状态和调度运行历史。
- 增强自选股管理，支持导入、导出、批量编辑和历史提醒记录。
- 增加因子研究结果页面，让当前 `docs/FACTOR_RESEARCH.md` 和 CSV 报告可视化。

### P2：量化研究深化

- 补齐现金流质量、分红、北向资金、融资融券和分析师预期数据。
- 扩展因子 IC 框架，做更严格的样本外和滚动验证。
- 引入组合优化、行业约束、换手约束和风险归因。

### P3：实盘能力

- 明确券商接口和合规边界。
- 先实现只读账户同步，再实现人工确认下单。
- 最后再考虑低权限、强风控、可回滚的自动交易闭环。
